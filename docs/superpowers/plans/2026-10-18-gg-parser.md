# GG Poker Phase 1A Parser Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [x]`) syntax for tracking.

**Goal:** Parse all three real GG exports into exact, validated tournament/hand
records with structured diagnostics and an explicit legacy replay projection.

**Architecture:** Split source text once, recognize small GG tokens, assemble raw
hands, then normalize using shared schemas, occupied-seat positions, and an exact
chip ledger. A separate adapter projects canonical records to existing replay
contracts without modifying the engine or UI.

**Tech Stack:** Existing strict TypeScript, Zod 3, Vitest 5, Node fixture reads in
tests only. No dependencies, network, Context7, or AI APIs are needed.

**Spec:** [Approved design](../specs/2026-10-18-gg-parser-design.md), approved
2026-10-18. The plan was approved for native execution with independent final review.

## Global Constraints

- Runtime AI cost is $0.
- Do not change UI, routing, mock data semantics, `src/domain/replay.ts`, training,
  strategy, analysis, upload presentation, persistence, or AI services.
- Add no dependencies or external calls.
- Keep real fixtures unchanged in `tests/fixtures/gg/`.
- Use safe integer numbers for chips; reject fractions, negatives, unsafe values,
  and unsafe sums.
- Preserve source facts; leave ISO currency and timezone null with warnings.
- Keep existing unrelated visual work intact.
- Do not mark Phase 1 complete or start Phase 1B.

## Review Focus

1. Mixed/duplicated imports must fail atomically without a partial tournament
   (Task 5/6).
2. Bad comma grouping, unsafe totals, leap days, and impossible local timestamps
   must fail without floating-point or machine-timezone normalization (Task 1/4).
3. Repeated same-owner cards must validate while cross-owner duplicates and
   conflicting later reveals fail (Task 5/6).
4. Summary-only card disclosure and repeated unlabeled awards must retain source
   meaning and reconcile independently (Task 2/5/6).
5. Returns after an all-in must preserve canonical truth and projected finances,
   with legacy rendering limits explicitly reported (Task 4/7).

## File and interface map

- `src/parsers/gg/diagnostics.ts`: `ParseErrorType`, `ParserIssue`, `ParserWarning`,
  and internal typed `GgParseError`. Issues carry type/message/sourceName/handId/
  sourceHandNumber/lineNumber/rawLine where available.
- `src/parsers/gg/split.ts`: `SourceLine { number, text }`,
  `HandBlock { sourceHandNumber, startLine, endLine, rawText, lines }`, and
  `splitGgHands(text: string): HandBlock[]`.
- `src/parsers/gg/values.ts`: `parseChips(value: string, source: SourceLine): number`,
  `parseBuyIn(title: string, source: SourceLine): ExactMoney | null`,
  `parseLocalTimestamp(value: string, source: SourceLine): LocalTimestamp`, and
  `parseCards(value: string, source: SourceLine): Card[]`. Cards input includes
  one complete bracket pair. Bad input throws typed internal errors.
- `src/parsers/gg/tokens.ts`: discriminated `GgToken` and
  `tokenizeGgLine(line: SourceLine): GgToken`, using source numbers throughout.
- `src/parsers/gg/rawHand.ts`: `RawGgHand` and
  `parseRawGgHand(block: HandBlock): RawGgHand`; owns structural section order.
- `src/domain/handHistory.ts`: schemas/types `HandHistoryEvent`, `ImportedHand`,
  `ImportedTournament`, `ExactMoney`, `LocalTimestamp`, exact source/table/result/
  board contracts, and typed `HandHistoryValidationError`. Domain modules must
  not import GG parser diagnostics; the parser maps domain faults to public issues.
- `src/domain/positions.ts`: `assignPositions(seats: readonly number[],
buttonSeat: number, tableSize: number): Record<number, Position>`.
- `src/domain/handLedger.ts`: `HandLedger(players: readonly Player[])` with
  `commitment(actorId: string): number`, `apply(event: HandHistoryEvent): void`,
  `snapshot(): LedgerSnapshot`, and `finish(totalPotChips: number): LedgerSnapshot`.
  Snapshots have `potChips` and per-player integer records `stacks`,
  `contributions` (gross), `returns`, and `awards`. Finish reconciles gross minus
  returns and total awards against the declared pot, requiring remaining pot zero.
- `src/parsers/gg/normalize.ts`: `normalizeGgHand(raw: RawGgHand): ImportedHand`.
- `src/parsers/gg/index.ts`: public `parseGgTournament(text, options?): ParseResult`;
  `ParseResult` is `{ ok: true, tournament, warnings }` or
  `{ ok: false, errors, warnings }`.
- `src/domain/replayAdapter.ts`: `toReplayHand(hand: ImportedHand):
ReplayAdaptation`, returning `{ hand: Hand, diagnostics, sourceEventIds }`.
- Co-located `.test.ts` files follow existing Vitest discovery. Test helper
  `src/parsers/gg/fixtureTestUtils.ts` reads the three exact fixture filenames and
  extracts source hands by ID. It is imported by tests only.
- `docs/specs/gg-parser.md`: supported grammar, API, warnings, TODOs, adapter limits,
  fixture evidence, verification results. Roadmap files track the actual status.

`Position` uses `z.infer<typeof positionSchema>`; add an exported alias in existing
schemas only if needed. Other legacy schemas and mock data retain their behavior.
